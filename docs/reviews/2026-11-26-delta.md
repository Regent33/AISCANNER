# Review of the code added after the 2026-11-25 reviews

Scope: `escl.py`, `scanners.py`, `api_report.py`, `analysis.py`, `report_pdf.py`, `cloud.py` additions, the scanner picker, edit mode and the Report screen. Passes: correctness and maintainability (code-reviewer), security (as in `docs/security/run-1`), and UI (apple-design / taste rules, checked on the running app).

- **Fixed (cost)**: in cloud mode, a question the model could not key was sent to the model again on every report view. It is now marked as tried; a new key upload resets it.
- **Security**: the new endpoints sit behind the host allowlist and the same-origin write check. `/api/scanners/check` fetches a teacher-supplied address (SSRF shape) but is reachable only from this computer. WIA and SANE inputs are passed as data, never as script text or options. PDF export holds no names or IDs (G8 check). Report GET writes derived data (topic mapping, cached reteach), which is safe because it never takes request input.
- **UI**: the Report matches the design tokens (one accent, bars without tracks, plain copy). Edit mode reuses the wizard and explains that an empty step keeps the current value. The scanner picker has empty, searching and error states.
- **Line limit**: every `.py`, `.ts` and `.tsx` file in `backend`, `frontend/src`, `frontend/e2e`, `fixtures`, `gates` and `tests` is at most 250 lines (largest: `backend/app/grading.py`, 211).
