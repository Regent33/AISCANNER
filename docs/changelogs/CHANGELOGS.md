# Changelog

Newest first. One entry per meaningful change; gate numbers refer to SPEC section 11.

## 2026-11-26

- Added `Start-AISCANNER.cmd` for Windows. It serves the built Settings page and its API together on port 8000. A frontend-only launch on port 5173 needs this backend for its API requests. The launcher respects `SCANNER_DATA` and recognizes the existing demo database on first use.

- Added OpenRouter and hosted NVIDIA NIM with editable model IDs, separate key pools and automatic fallback on rate limits. Grading resumes after a key cooldown. Expanded the README with Windows setup, a printable sample quiz and the scan-to-report workflow.

- **Print test** (owner request): a vector PDF of the test, built from the answer key in the format the scanner reads (corner marks, "Page k of N", Name / ID / Year / Section block, bubbles, answer boxes). Available on each test card and as the last step of the New test wizard. Downloading it also sets pages per paper, the student details area and the sample page. Keys may now have 2-5 options per multiple-choice question (A-E). Fixed: the blacked-out identity block could be detected as an answer box after a skewed scan, which flagged papers `layout_mismatch`. Boxes mostly inside an identity region are now ignored.
- **Fixed: the frontend data layer was never committed.** `.gitignore` had `data/`, which ignores every folder named `data` at any depth, including `frontend/src/features/*/data/`. It is now `/data/` (repo root only), and the five folders are in git. Found while testing G10 in a fresh worktree.
- **G9 pass**: the 600-paper stress batch is graded in full; a hard kill at 240 papers followed by a resume gives byte-for-byte identical results; peak memory 468 MB; 38.8 papers/min; estimated cloud cost $16.63 per 500 papers (estimate only, no cloud calls).
- **G10**: Playwright golden path (create test, upload batch, review with the keyboard, report, PDF download), home to report in 1 click, review latency with 500 queued items timed inside the page. `README.md` added.
- **G8 report**: topic mapping runs once per test (offline TF-IDF over stemmed words, with math notation such as 1/2, % and 3x+5=17 read as fraction, percentage and equation; Claude in cloud mode). Keyless questions get a key (offline: the most common student answer; cloud: Claude, from the question text only) marked unverified. Per-question and per-topic miss rates (partial credit and teacher overrides included). Reteach activities for the top 3 weak topics, generated once and kept. `GET /api/tests/{id}/report` and a 4-section PDF with no student names or IDs. Fixed: a string in `cloud.py` was broken by a literal newline.
- **Edit an existing test**: each test card has Edit, which reopens the wizard at the answer key. Replace the key, the syllabus (paste or .txt/.pdf) or the student details area; an empty step keeps what the test has.

## 2026-11-25

- **Security audit run 1** (`docs/security/run-1/REPORT.md`). Fixed a HIGH: DNS rebinding chained with PowerShell injection (curly quotes break out of PowerShell strings). Fixed a MEDIUM: cross-site `text/plain` POST could replace the answer key. Now: Host allowlist, same-origin writes, JSON only with `application/json`, and WIA inputs passed as environment variables. Regression tests in `tests/test_security.py`.
- **Any printer-scanner** (owner request): new `scanners.py` + `escl.py`. Scanners are found automatically: Windows WIA drivers, eSCL/AirScan/Mopria network printers (mDNS), and SANE on Linux. A network printer can also be added by IP address. The Scan screen has a scanner picker (remembered between visits), and scan errors show on the batch ("No scanner found", "could not reach the printer"). Tested end to end over real HTTP against a mock eSCL printer, including from the UI. `docs/SCANNER_CHECKLIST.md` replaces the WIA-only checklist. No real hardware tested yet (G11).
- **Year and Section** (owner request): the printed test's student block now has Name, ID, Year and Section. All four are read locally by OCR. Each handwritten value is matched to the printed label on its left, and a short value the detector misses (a lone digit) is read from the strip beside its label. They are stored per paper, blacked out with the rest of the block, shown and editable in Review (`PATCH /api/papers/{id}` takes `year` and `section`). The fixtures were regenerated with the new block. Answer ground truth is unchanged because the new values come from a separate random stream.
- **CloudProvider** (Claude via the official `anthropic` SDK, default `claude-opus-5-5`, server-side refusal fallbacks) with a metadata-only audit of every outbound request. G7 privacy gate: a capture transport replaces the network in cloud mode, and a socket guard blocks every non-loopback connection in local mode.
- **Teacher UI** built in the owner's layered architecture (`frontend/src/app`, `shared/{kernel,ui,infrastructure,utils}`, `features/{tests,scan,review,report,settings}/{domain,data,presentation,di}`). Screens: Tests list and a 4-step New test wizard (details, answer key, syllabus, name/ID area drawn on page 1 by mouse or keyboard); Scan (scanner, folder watch, upload, live progress, pause/resume, finish); Review (keyboard-first queue with redacted crops, optimistic updates); Report (weak topics, reteach, per-question table, PDF button; backend endpoint lands in G8); Settings. Light and dark themes from semantic tokens.
- Design review (`docs/reviews/2026-11-25-ui-design.md`): control borders raised to 3:1+ contrast, keyboard path for the identity box, blank answers no longer flood Review.
- Code review (`docs/reviews/2026-11-25-code.md`): `HttpClient` no longer throws on empty bodies; malformed JSON returns 422.
- Backend: `main.py` split into `api_tests`, `api_batches`, `api_review`, `api_settings` routers; grade stage moved to `grade.py`; batch progress (graded, flagged, review pending, ETA); in-place column migrations so existing databases keep their data. Fixture generator split into `render.py` and `generate.py` with byte-identical output.
- **G6 pass**: written answers graded by local OCR with fuzzy matching of each part (any order, partial credit). Review queue API (`GET /api/batches/{id}/review`, `PATCH /api/responses/{id}`, `PATCH /api/papers/{id}`) with on-demand redacted crops. Fixed: a `/` inside an answer such as `3/8` was parsed as two alternatives. Alternatives are now separated by ` / ` with spaces.
- **G5 pass**: answer areas detected on each registered page (box lines, Hough bubbles with ring refinement), printed question numbers read by OCR so a missing page cannot shift numbering, MCQ read by bubble darkness. One redaction choke point (`pipeline.redacted_page`) feeds all grading.
- **G4 pass**: fiducial registration (any rotation), "Page k of N" labels, grouping that flags missing, duplicate and unreadable pages and never drops one, local student-ID OCR, pseudonymous `S-0001` refs.
- **G3 pass**: ingestion by upload (images and PDF), folder watcher (about 1 s latency), MockScanner trigger, WIA adapter, and a manual hardware checklist (`docs/WIA_CHECKLIST.md`).
- **G2 pass**: answer key and syllabus by paste, .txt or .pdf; keyless questions (`key_source=ai`); redaction regions; sample page upload.
- **G1 pass**: FastAPI + SQLite + job worker that recovers after a hard kill; React shell served at `/`.
- **G0 pass**: deterministic fixture generator (3 tests with 1, 2 and 4 pages, 30 papers each, plus a 600-paper stress set) with ground-truth schema.
